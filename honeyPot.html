Microsoft Azure Honeypot & SIEM Integration

Home

I configured an Azure-hosted virtual machine combined with an Intrusion Prevention System (IPS) as a honeypot. Syslogs were then collected and ingested into a SIEM tool to observe failed SSH login attempts.

Honeypot Deployment on Azure:
- Set up a disposable internet-facing ubuntu virtual machine
- Moved real administrative SSH access to a random port
- Configured the Network Security Group (NSG) to allow public traffic to port 22
- Configured the Network Security Group (NSG) to block all traffic from the VM to prevent it from being used as a bot
- Installed and configured Fail2Ban IPS to track and ban aggressive IP addresses on port 22

Log Collection:
- Azure VM (honeypot) generates authentication logs (e.g., SSH login attempts)
- Azure Monitor Agent (AMA) collects Syslogs and sends them to a Log Analytics Workspace using Data Collection Rules (DCR)
- Log Analytics streams/exports logs to Azure Event Hubs
- Splunk Add-on for Microsoft Cloud Services ingests logs from Event Hubs into Splunk Enterprise
- Splunk Enterprise processes and visualizes the logs for security monitoring and analysis

Key Challenges and Solutions

Challenge Solution
The default Azure "Diagnostic Settings" menu pushed for the old Linux Diagnostic Extension (LAD), which is being retired in March 2026. Used the modern Azure Monitor Agent (AMA) by creating a custom Data Collection Rule (DCR), future-proofing the implementation.
Azure restricted Ubuntu Syslog data to only be sent to Log Analytics Workspaces, hiding the "Event Hub" option for Splunk export Used Log Analytics and created a Data Export rule. This mirrored data from the workspace to the Event Hub.
Fail2Ban IPS failing to start Discovered that the jail.local file had a duplicate configuration header. Rectified the error, started the service, and confirmed that malicious IPs were being banned.
Sending only necessary logs to Splunk Configured the DCR to filter specifically for AUTH and AUTHPRIV logs, capturing only critical security login events.

Building this honeypot was a stark reminder of how hostile the internet is. Within minutes of deployment, it was targeted by numerous automated attacks, highlighting the importance of proactive security measures.
